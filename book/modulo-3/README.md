# Módulo III — Sistemas operacionais

[← Módulo II](../modulo-2/README.md) · [Índice do livro](../README.md) · [Página inicial](../../README.md)

Um programa possui instruções, memória e arquivos, mas não trabalha sozinho. Outros programas disputam o mesmo equipamento, identidades diferentes precisam de limites e serviços devem continuar funcionando sem alguém diante da tela.

Este módulo investiga quem organiza essa convivência. Começamos pelo papel do sistema operacional e avançaremos para Linux, Windows, interfaces de comandos, permissões, serviços e isolamento. O objetivo não é memorizar duas coleções de comandos: é reconhecer qual componente realiza uma operação, sob qual identidade e com quais garantias.

## Como ler

O capítulo 11 utiliza os fundamentos dos capítulos 6 a 10 e explica os termos novos antes de depender deles. Seu exemplo executável é opcional, limitado ao Linux e a arquivos temporários próprios. Não é necessário trocar de sistema operacional, instalar uma máquina virtual ou modificar permissões para acompanhar a narrativa.

Consulte o [glossário](../glossario.md) e as referências de cada unidade. A introdução de um mecanismo de proteção não equivale a um treinamento completo de configuração nem à validação de uma máquina real. Os estados e pendências ficam no [controle editorial](../../editorial/publication-status.md).
