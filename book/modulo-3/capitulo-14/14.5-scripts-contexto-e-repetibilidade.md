# 14.5 — Da sequência digitada a um contrato repetível

[← Seção 14.4](14.4-status-condicoes-e-controle.md) · [Próxima seção →](14.6-automacao-e-fronteiras-de-confianca.md)

Salvar comandos em um arquivo é fácil. Transformar essa sequência em algo que outra pessoa consiga executar, compreender e investigar exige mais cuidado.

O primeiro passo é parar de tratar a sessão atual como parte invisível do programa.

## Um script declara qual linguagem espera

Um **script** é um arquivo de instruções para um interpretador. No recorte deste capítulo, arquivos `.bash` usam Bash, e arquivos `.ps1` usam PowerShell. A extensão comunica intenção, mas a maneira de iniciar o arquivo também importa.

Em sistemas Unix, uma primeira linha como `#!/usr/bin/env bash`, chamada **shebang**, pode indicar o interpretador na execução direta de um script executável. Usar `env` faz a localização depender de `PATH`. Já `bash arquivo.bash` escolhe Bash explicitamente para ler o arquivo; não transforma o restante do conteúdo em outra linguagem. [S38](referencias.md#s38)

Não vamos alterar o bit de execução nesta unidade. Os exemplos Bash são iniciados com `bash arquivo.bash`, e o aprofundamento das permissões permanece no capítulo 15.

PowerShell possui formas distintas de executar arquivos, incluindo `pwsh -File`. O nome `pwsh` identifica a linha PowerShell 7, não o executável tradicional `powershell.exe`. Usar um processo novo ou executar um script na sessão existente pode mudar escopos e códigos retornados. [S39](referencias.md#s39)

## O que a sessão estava oferecendo sem você perceber

Um roteiro pode depender do diretório corrente, da resolução de comandos, de variáveis de ambiente, de aliases, de funções já carregadas e de opções do interpretador.

Bash possui regras diferentes para arquivos de inicialização em sessões de login, interativas e não interativas. Um script não deve presumir que tudo definido no `.bashrc` de uma pessoa estará presente. A variável `BASH_ENV` também pode apontar para conteúdo executado na inicialização não interativa. [S40](referencias.md#s40)

PowerShell usa **profiles**, scripts de inicialização que podem configurar sua sessão. A opção `-NoProfile` evita seu carregamento na invocação correspondente. Isso reduz uma fonte de variação; não cria uma sandbox nem torna qualquer script seguro. [S41](referencias.md#s41)

Em nossos testes, cada processo recebe um contexto controlado. Essa escolha serve para atribuir as diferenças observadas ao exemplo, em vez de ao perfil pessoal de alguém.

## Variável do shell não é automaticamente variável de ambiente

Em Bash, uma atribuição como `rotulo=Aurora` define uma variável do shell. `export rotulo` marca esse valor para integrar o ambiente de comandos iniciados depois. O programa filho recebe uma herança; ele não ganha acesso de escrita à sessão do pai. [S8](referencias.md#s8)

No PowerShell, `$rotulo` e `$env:rotulo` também representam coisas distintas. A primeira é uma variável da linguagem no escopo correspondente; a segunda acessa uma variável de ambiente do processo. Modificar o ambiente de um processo não atualiza retroativamente todas as execuções já iniciadas. [S42](referencias.md#s42)

O mesmo cuidado vale para diretórios. Mudar o diretório dentro de um processo filho não é uma maneira de mudar o diretório do shell pai. Essa separação explica por que um roteiro pode “funcionar” internamente e não deixar a sessão na pasta imaginada.

## Executar um arquivo ou incorporar suas instruções

Em Bash, `bash arquivo.bash` inicia outro interpretador. `. ./arquivo.bash`, também chamado **source**, lê as instruções no contexto do shell atual. Variáveis, funções e mudanças de diretório podem permanecer ali. [S8](referencias.md#s8)

No PowerShell, **dot-sourcing**, escrito com ponto e espaço antes do caminho, executa o script no escopo atual. Uma chamada normal de script não é equivalente a essa incorporação. [S19](referencias.md#s19)

Portanto, carregar um arquivo com `source` ou dot-sourcing não é uma forma mais segura de “apenas ler configuração”. É executar código com efeitos sobre a sessão. Um arquivo de dados deve ser interpretado como dados, por uma interface adequada ao formato.

## Um roteiro completo, com um problema pequeno

Vamos construir um resumo de estados de empréstimo. Para evitar qualquer dependência do catálogo real, cada estado é recebido como um argumento. O contrato do exemplo é deliberadamente curto: de um a 256 valores, cada um exatamente `disponivel` ou `emprestado`.

O script [resumo-estados.bash](exemplos/resumo-estados.bash) é:

```bash
if (( $# == 0 || $# > 256 )); then
    printf '%s\n' 'uso: bash resumo-estados.bash ESTADO [ESTADO ...]' >&2
    exit 2
fi

disponiveis=0
emprestados=0

for estado in "$@"; do
    case "$estado" in
        disponivel) disponiveis=$((disponiveis + 1)) ;;
        emprestado) emprestados=$((emprestados + 1)) ;;
        *)
            printf '%s\n' 'estado invalido; nenhum resumo produzido' >&2
            exit 2
            ;;
    esac
done

printf 'disponiveis=%s\nemprestados=%s\n' "$disponiveis" "$emprestados"
```

`((...))` faz a comparação aritmética da quantidade. `$((...))` calcula um novo valor. `case` escolhe um ramo segundo o texto; `*)` trata os demais casos, e `;;` encerra cada ramo. São recursos de Bash, não uma promessa de compatibilidade com qualquer `sh`. [S43](referencias.md#s43)

O laço conserva os argumentos com `"$@"`. A saída de resultados só é produzida depois que todos os valores passaram pela validação. Em caso inválido, há diagnóstico em `stderr` e código 2; não inventamos um total parcial com aparência de resultado completo.

A chamada:

```bash
bash resumo-estados.bash disponivel emprestado disponivel
```

produz:

```text
disponiveis=2
emprestados=1
```

Esse comportamento, o limite de entradas e os casos inválidos foram testados. O exemplo não lê arquivos de outras pessoas, não altera o catálogo e não descobre falhas de segurança.

## A mesma finalidade, respeitando o PowerShell

O script [Resumo-Estados.ps1](exemplos/Resumo-Estados.ps1) recebe uma coleção de strings, valida os estados e produz um objeto com as propriedades `Disponiveis` e `Emprestados`.

A chamada dentro do PowerShell é:

```powershell
& ./Resumo-Estados.ps1 -Estados @('disponivel', 'emprestado', 'disponivel')
```

O resultado não precisa ser convertido imediatamente em linhas. Pode continuar como objeto:

```powershell
$resumo = & ./Resumo-Estados.ps1 -Estados @('disponivel', 'emprestado')
$resumo.Disponiveis
```

Na implementação, a comparação é explicitamente sensível a maiúsculas e minúsculas. Assim, `DISPONIVEL` não é aceito silenciosamente por uma comparação padrão diferente da usada no Bash. Quando a entrada é inválida, o script usa `throw`; não retorna um objeto de resumo. [S44](referencias.md#s44)

A forma de encerramento também é intencional. O objeto viaja no fluxo de sucesso. O erro é terminante. Se você iniciar outro processo `pwsh`, a saída atravessa uma fronteira de processo e pode ser apresentada como texto; não presuma que outro programa recebeu um objeto vivo só porque a implementação original usou PowerShell. [S26](referencias.md#s26) [S39](referencias.md#s39)

O exemplo correspondente e os testes de cada plataforma ficam separados. Não precisamos fingir que os dois shells possuem a mesma gramática para comparar suas responsabilidades.

## Repetibilidade não é uma propriedade do nome do arquivo

Executar duas vezes o mesmo script não basta para obter o mesmo efeito. A entrada, o ambiente, o estado externo e as versões também participam.

Nosso resumo não modifica dados externos. Repetir a mesma chamada produz a mesma contagem no contexto testado. Isso não demonstra que um futuro importador será **idempotente**: uma operação idempotente precisa preservar o mesmo efeito pretendido quando repetida, em vez de criar novos efeitos a cada tentativa.

Imagine uma automação que acrescente “importação concluída” a um arquivo a cada execução. Ela pode imprimir a mesma frase e ainda modificar o estado de maneira cumulativa. Saída igual e efeito igual são comparações diferentes.

Um roteiro confiável torna explícitos entrada, saída, pré-condições, falhas e efeitos. A quantidade de linhas importa menos que a clareza desse contrato.
