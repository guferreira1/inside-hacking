# 14.1 — A janela não é o interpretador

[← Abertura](README.md) · [Próxima seção →](14.2-argumentos-aspas-e-expansoes.md)

A janela tem fundo escuro, um cursor e algumas palavras. Isso basta para saber qual linguagem ela aceita? Não. A aparência pode ser quase idêntica enquanto os programas que interpretam o texto são diferentes.

Esse detalhe importa logo no primeiro contato. Colar uma instrução de Bash no PowerShell não é como mudar a fonte de um documento. É entregar uma frase a outro interpretador, com outra gramática.

## Três responsabilidades, não uma única ferramenta

Um **terminal** oferece um meio de interação com aplicações orientadas a texto. Em um computador pessoal, normalmente usamos um **emulador de terminal**, um programa que apresenta essa interação em uma janela. O **shell** lê e interpreta comandos. Os programas chamados por ele realizam operações específicas.

O Windows Terminal, por exemplo, pode hospedar sessões de PowerShell, do Prompt de Comando e de ambientes Linux disponíveis na máquina. Abrir outra aba não garante que ela execute o mesmo shell. A documentação do Windows distingue a aplicação hospedeira dos shells usados dentro dela. [S1](referencias.md#s1)

Uma representação simplificada é:

```text
pessoa escreve ou cola uma linha
              ↓
terminal oferece a interação
              ↓
shell interpreta comandos e argumentos
              ↓
comandos internos, funções ou programas executam operações
              ↓
sistema operacional atende às solicitações permitidas
```

O desenho organiza responsabilidades; não descreve todas as chamadas e buffers envolvidos. Um programa também pode iniciar outro diretamente, sem um shell intermediário. E um shell pode executar um arquivo de comandos sem existir uma janela aberta.

A **interface de linha de comando**, ou **CLI**, é a forma de interação por comandos e argumentos. Não é sinônimo de shell: um programa próprio de conversão de arquivos pode oferecer uma CLI sem interpretar laços, variáveis ou pipelines por conta própria.

## Por que ainda falamos em terminal e console

O vocabulário vem de sistemas em que um terminal era um equipamento separado, usado para conversar com um computador. Nos sistemas atuais, parte dessa interface é reproduzida por software.

Em Linux, um **pseudoterminal**, ou **PTY**, é um par de dispositivos virtuais que oferece uma interface semelhante à de um terminal. Um lado é usado pelo programa que controla a interação; o outro pode ser usado pelo shell e pelas aplicações. Isso ajuda a entender por que um programa pode distinguir a execução interativa de uma execução com a saída ligada a um arquivo. [S2](referencias.md#s2)

A palavra **console** varia com o contexto. No Windows, existe uma infraestrutura de entrada e saída para aplicações de console; em outro texto, console pode designar uma interface de administração. Não devemos deduzir toda a arquitetura pelo nome informal usado para a janela. [S3](referencias.md#s3)

Para este capítulo, a separação mais útil é simples: **a interface apresenta a conversa; o interpretador dá significado aos comandos**.

## Shell também é linguagem

Bash é um shell do projeto GNU. Seu nome significa *Bourne-Again SHell*, referência ao shell de Stephen Bourne. Além de iniciar programas, Bash possui variáveis, condições, repetições e funções. A mesma linguagem pode ser usada interativamente ou a partir de um script. [S4](referencias.md#s4)

PowerShell também combina shell e linguagem de automação, mas seu modelo inclui objetos e cmdlets, que conheceremos adiante. Não é uma tradução palavra por palavra do Bash. Existem Windows PowerShell e a linha PowerShell 7; versão e ambiente precisam ser registrados quando um comportamento depender deles. [S5](referencias.md#s5)

O **Prompt de Comando**, associado a `cmd.exe`, é outro interpretador. Ele possui seus próprios comandos, operadores e arquivos de lote. Não é o nome antigo do PowerShell. Por exemplo, a expansão de variáveis escrita como `%NOME%` pertence a esse contexto, não ao Bash. [S6](referencias.md#s6)

Também não devemos tratar `sh` e Bash como equivalentes absolutos. Um script que usa recursos específicos do Bash deve declarar essa dependência, em vez de supor que qualquer interpretador chamado `sh` aceitará o texto. O nome da linguagem faz parte do contrato do exemplo. [S4](referencias.md#s4)

## O que existe depois do prompt

O **prompt** é o convite visual para digitar. Pode mostrar usuário, diretório, nome da máquina ou apenas um símbolo. Ele é configurável: não comprova identidade, privilégios nem sucesso da última operação.

Neste livro, os blocos de comandos não trazem um `$` ou `PS>` decorativo no início da linha. Assim, você não precisa descobrir quais caracteres pertencem ao código e quais faziam parte do prompt da captura.

Considere, em Bash:

```bash
printf '%s\n' 'Aurora'
```

`printf` é o nome do comando. Os textos seguintes são argumentos. O primeiro define como apresentar o segundo: `%s` representa texto, e `\n` pede uma quebra de linha. As aspas delimitam partes da escrita; não serão necessariamente caracteres recebidos pelo comando. A saída do exemplo é `Aurora`, seguida de uma quebra de linha. [S7](referencias.md#s7)

Ainda não há arquivo, rede nem exploração. Há uma instrução, um interpretador e uma saída. É a partir desse caso pequeno que vamos construir o restante.

## Nem todo comando corresponde a um executável

Um comando pode ser um **builtin**, implementado dentro do shell; uma **função**, definida na própria linguagem; um **alias**, que abrevia uma escrita; ou um programa externo.

`cd` precisa alterar o diretório de trabalho do shell que continuará recebendo comandos. Executar um programa filho que muda apenas o próprio diretório não produziria o mesmo efeito no pai. Por isso, a distinção entre comando interno e processo separado não é só uma otimização. [S8](referencias.md#s8)

No Bash, uma consulta útil é:

```bash
type -a printf
help printf
```

A primeira mostra as resoluções conhecidas para o nome. A segunda consulta a ajuda do builtin. A saída de `type -a` depende do ambiente; não há uma lista universal de caminhos para decorar. [S7](referencias.md#s7)

No PowerShell, consultas correspondentes ao seu próprio modelo são:

```powershell
Get-Command Get-Content
Get-Help Get-Content
```

`Get-Command` informa o que o nome identifica; `Get-Help` apresenta a ajuda disponível. Um **cmdlet** é um comando integrado ao modelo de execução do PowerShell, normalmente com parâmetros e objetos de entrada e saída. O formato verbo-substantivo ajuda na organização, mas o contrato de cada comando ainda precisa ser consultado. [S5](referencias.md#s5) [S9](referencias.md#s9)

Antes de copiar uma linha da internet, portanto, a primeira pergunta não deve ser “em qual janela colo?”. Deve ser: **qual interpretador e qual comando entenderão esse texto?**
