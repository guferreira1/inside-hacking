# 7.4 · Guardar não é apenas receber uma escrita

[← Seção 7.3](7.3-memoria-e-cache.md) · [Próxima seção →](7.5-dispositivos-e-firmware.md)

Chegamos ao botão Salvar. O editor pede que a nova versão deixe de depender apenas de seu estado de trabalho. Mas existe uma distância entre pedir uma escrita, receber uma confirmação e saber qual garantia de persistência foi atendida.

Para entender essa distância, vamos primeiro olhar para o armazenamento.

## Disco e SSD: mesma função ampla, mecanismos diferentes

Um **HDD**, *Hard Disk Drive*, utiliza superfícies magnéticas em pratos que giram e cabeças para leitura e escrita. Localizar o trecho desejado envolve movimento e posição. Um **SSD**, *Solid-State Drive*, utiliza armazenamento de estado sólido; nos SSDs de flash NAND, não existe esse mesmo percurso mecânico de cabeça e prato. A apresentação das tecnologias em *Computation Structures* descreve essa diferença de mecanismo. [S4](referencias.md#s4)

Isso não nos autoriza a atribuir um tempo fixo a qualquer disco ou SSD. O pedido, a organização dos dados, as filas e a implementação importam. Ler uma sequência extensa e acessar muitos trechos espalhados são cargas distintas.

A palavra **flash** designa uma tecnologia de memória não volátil. Nos SSDs NAND, escrever e apagar não são operações simétricas: a programação ocorre em páginas, e a preparação para reutilização envolve apagar blocos. O controlador administra a movimentação de dados válidos e a recuperação de espaço; a Kingston descreve esse trabalho como parte da coleta de lixo interna do SSD. [S6](referencias.md#s6)

O sistema vê uma interface lógica de armazenamento. Não precisa comandar cada célula física para salvar uma frase. Essa separação permite o funcionamento do dispositivo, mas também significa que a imagem simples “o programa substituiu exatamente aquele ponto físico” pode não representar a operação interna.

## Apagar o nome não responde tudo sobre os bytes

Excluir um arquivo e eliminar de maneira verificável todas as representações de seu conteúdo são objetivos diferentes. Na descrição da Kingston, o sistema de arquivos marca o espaço como não utilizado e mecanismos como TRIM comunicam ao dispositivo que determinados dados lógicos já não precisam ser preservados. Isso participa da administração do armazenamento; não é uma demonstração universal de sanitização. [S6](referencias.md#s6)

No exemplo do editor, podemos formular uma pergunta sem executar nada: se existiram cópias de trabalho, cópias de segurança e armazenamento interno administrado pelo controlador, apagar um único nome prova o destino de todas elas? Não. Precisaríamos analisar cada lugar e o procedimento aplicado.

Não vamos aprofundar recuperação forense neste capítulo. Basta guardar a distinção entre uma operação na interface de arquivos e uma afirmação sobre todos os estados físicos que possam conter informação.

## Formato não é protocolo

Ao observar um SSD, o leitor pode encontrar siglas como M.2, SATA, PCIe e NVMe. Elas não são quatro palavras intercambiáveis para “disco rápido”.

**M.2** identifica uma especificação de formato e conexão usada por diferentes dispositivos. **SATA**, *Serial ATA*, é uma interface de armazenamento. **PCIe**, *Peripheral Component Interconnect Express*, é uma interconexão. **NVMe**, *Non-Volatile Memory Express*, define uma interface de comandos para armazenamento não volátil; em SSDs locais, é comum utilizá-la sobre PCIe. A Kingston distingue formato físico de interface e observa que nem todo SSD M.2 utiliza NVMe. [S7](referencias.md#s7)

Essa separação já basta para evitar uma conclusão apressada sobre compatibilidade. A aparência de um encaixe não responde sozinha que interfaces a plataforma aceita. Tampouco escolher uma sigla substitui a análise da carga que queremos executar. Não estamos recomendando uma compra; estamos aprendendo a ler a descrição de um componente.

## Quem confirmou a gravação?

Voltemos ao arquivo. Para acelerar operações, o software pode manter dados em memória antes de enviá-los ao armazenamento. A camada de arquivos do Linux descreve operações intermediadas pelo cache de páginas e a posterior escrita dos dados. [S10](referencias.md#s10)

O próprio dispositivo pode possuir **cache de escrita volátil**. Nesse caso, pode indicar conclusão de uma operação antes de os dados alcançarem o meio não volátil. A documentação do kernel Linux apresenta mecanismos de *flush* e de confirmação de persistência justamente para controlar essa situação. [S9](referencias.md#s9)

Compare dois contratos imaginários. No primeiro, uma resposta significa “aceitei sua solicitação e mantenho uma cópia temporária”. No segundo, significa “a gravação chegou ao armazenamento não volátil nas condições especificadas”. Se a energia desaparecer depois da primeira resposta, o resultado pode ser diferente do que seria depois da segunda.

A conclusão não é desconfiar de todo botão Salvar. É perguntar qual contrato a aplicação utiliza e quais garantias as camadas abaixo oferecem. Algumas aplicações exigem confirmação mais forte em operações específicas; outras adiam trabalho. O efeito precisa ser analisado no caminho completo, inclusive erros e capacidades do dispositivo.

**Flush**, nesse contexto, não quer dizer simplesmente “apagar uma cache”. É solicitar o escoamento de escritas pendentes para o nível de armazenamento pertinente. Também não torna o equipamento imune a falhas físicas futuras. Uma garantia tem condições e limites.

## Persistência não é indestrutibilidade

Um meio não volátil conserva informação sem alimentação contínua, mas isso não elimina desgaste, defeito, alteração indevida ou perda do próprio equipamento. A definição de não volatilidade é sobre retenção, não disponibilidade eterna. [S15](referencias.md#s15)

No nosso cenário, uma cópia de segurança independente ajudaria numa classe de perda, mas não faria alguém esquecer uma informação já divulgada. Uma verificação de autorização protegeria certos acessos, mas não consertaria um dispositivo fisicamente danificado. Essa é a conexão com o capítulo 5: controles respondem a consequências e caminhos específicos.

Temos agora um percurso mais completo para a frase: estado de trabalho, pedido de gravação e persistência sob um contrato conhecido. A última peça do mapa envolve os dispositivos que movimentam dados e o software que os faz funcionar.
