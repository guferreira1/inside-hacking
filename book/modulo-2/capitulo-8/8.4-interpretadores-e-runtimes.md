# 8.4 · Interpretar também exige execução

[← Seção 8.3](8.3-carregamento-e-processos.md) · [Próxima seção →](8.5-contexto-e-diagnostico.md)

Até aqui, acompanhamos um caminho em C que produziu um executável nativo. Agora veja outra maneira de escrever a pequena conta:

```python
total = 2 + 3
print(total)
```

A primeira linha atribui o resultado ao nome `total`; a segunda solicita sua apresentação. Não é uma versão completa do programa anterior: omitimos o rótulo da saída para concentrar a atenção na execução.

Em um ambiente com Python, podemos entregar esse texto a um programa que conhece suas regras. Não precisamos construir manualmente um executável para a CPU antes de cada uso. Mas isso não significa que o hardware começou a entender a palavra `print` diretamente.

## O interpretador também é um programa

Um **interpretador** implementa a execução segundo as regras de uma linguagem ou representação. Ele próprio precisa funcionar sobre um ambiente real. A CPU continua executando instruções de máquina; o interpretador utiliza essas instruções para realizar as operações descritas pelo programa que recebeu.

Vamos tomar **CPython**, uma implementação de Python, como exemplo concreto. Seu código-fonte Python é compilado para uma representação intermediária chamada **bytecode**, utilizada pelo mecanismo de execução. Portanto, a descrição “interpretado” não implica ausência de compilação. O glossário oficial distingue essas camadas e ressalta que o bytecode não é uma interface estável entre todas as implementações e versões. [S10](referencias.md#s10)

Podemos representar o percurso conceitual assim:

```text
Texto Python → representação de código/bytecode → execução pelo runtime
                                                    ↓
                                  instruções da plataforma real
```

**Runtime**, ou ambiente de execução da linguagem, é o conjunto de mecanismos que sustenta esse trabalho. Pode incluir interpretação, gerenciamento de objetos, bibliotecas e outras funções. A palavra não designa necessariamente um único arquivo separado de tudo o mais.

## Compilar e executar continuam sendo perguntas diferentes

A função `compile` de Python torna essa separação observável: ela pode produzir um objeto de código a partir de uma string válida sem executar as atribuições descritas nessa string. O objeto pode ser posteriormente executado num contexto. Essa função e seus modos são documentados entre as funções embutidas. [S10](referencias.md#s10)

Nos testes editoriais, usamos exclusivamente a string constante `total = 2 + 3`. Antes de executar o objeto compilado, o contexto não continha a atribuição; depois, continha cinco. O exemplo não recebe entrada externa e não é uma recomendação de executar textos desconhecidos.

O ganho conceitual é perceber que o processamento pode ocorrer sem deixar um arquivo intermediário visível. “Não vi um executável novo” não demonstra “nenhuma tradução ocorreu”. Precisamos conhecer o mecanismo.

## Um arquivo pyc não é um executável nativo

Ao importar módulos, CPython pode conservar versões compiladas em arquivos `.pyc`, normalmente em `__pycache__`, para evitar parte do trabalho de preparação em usos posteriores. Esse cache está relacionado ao carregamento, não a uma conversão automática de todas as operações em instruções nativas independentes do interpretador. A documentação também distingue esse caso do script executado diretamente pela linha de comando. [S10](referencias.md#s10)

Por isso, duas conclusões seriam ruins. A primeira é exigir um `.pyc` no disco para acreditar que houve compilação. A segunda é assumir que o arquivo pode ser executado diretamente pela CPU, em qualquer versão, sem um runtime compatível.

A palavra **bytecode** informa uma representação para um mecanismo de execução. Não torna bytecodes de sistemas diferentes intercambiáveis só porque ambos utilizam bytes.

## Máquinas virtuais de linguagem e JIT

A **JVM**, *Java Virtual Machine*, especifica uma máquina abstrata e o comportamento do código que ela aceita, incluindo o formato `class`. Uma implementação deve respeitar essa semântica, mas possui liberdade sobre como realizá-la. A especificação admite, entre outras estratégias, tradução para instruções nativas durante o carregamento ou a execução. [S11](referencias.md#s11)

**JIT**, *just-in-time compilation*, é compilação realizada durante a execução. Uma implementação pode combinar interpretação e compilação de trechos, em vez de escolher uma única estratégia para toda a vida do programa. Não precisamos presumir que uma JVM particular compilou determinado método: isso exigiria observar aquela implementação e execução. [S11](referencias.md#s11)

Essa máquina virtual de linguagem não deve ser confundida com uma máquina virtual que oferece um ambiente para instalar um sistema operacional convidado. A pergunta central aqui é como executar uma representação de programa, não como apresentar um computador completo a outro sistema.

A portabilidade também tem condições. Um formato abstrato permite separar parte do código das instruções da CPU, mas ainda são necessários runtime, versão e dependências compatíveis. Código que depende de recursos particulares da plataforma não ganha acesso universal a esses recursos apenas por utilizar bytecode.

## A classificação pertence ao percurso

“C é compilado” e “Python é interpretado” podem orientar uma conversa inicial, mas deixam muita coisa escondida. Um percurso pode compilar antecipadamente, interpretar uma representação intermediária e compilar novamente durante a execução. A implementação e suas opções determinam o que de fato acontece.

Para investigar, prefira perguntas concretas: qual programa recebeu o fonte? Qual representação foi produzida? O que está sendo carregado? Que componente executa suas operações? Qual parte depende da plataforma?

Não precisamos escolher uma linguagem vencedora. Precisamos parar de tratar “compilado” e “interpretado” como explicações completas. A próxima seção acrescenta aquilo que nenhum desses rótulos descreve sozinho: o contexto em que o programa foi iniciado.
