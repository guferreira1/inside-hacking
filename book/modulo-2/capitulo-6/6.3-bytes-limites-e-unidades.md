# 6.3 · O tamanho muda a pergunta

[← Seção 6.2](6.2-binario-e-hexadecimal.md) · [Próxima seção →](6.4-texto-e-interpretacao.md)

Você já consegue interpretar uma sequência binária pequena. Agora precisamos combinar como agrupar suas posições e medir seu tamanho.

Neste livro, **byte** designa um grupo de oito bits, convenção utilizada pelos sistemas e protocolos que abordaremos. A palavra **octeto**, comum em especificações de rede, explicita esse grupo de oito. Na notação de unidades, `B` representa byte. [S3](referencias.md#s3) [S4](referencias.md#s4)

O byte não é obrigatoriamente uma letra, uma instrução ou uma posição isolada de um circuito. É uma unidade de representação. A pergunta sobre seu significado continua aberta.

## O que cabe em oito posições

Oito bits oferecem 256 padrões. Interpretados como um inteiro sem sinal, eles representam os valores de 0 a 255. O maior combina todos os pesos:

```text
11111111 = 128 + 64 + 32 + 16 + 8 + 4 + 2 + 1 = 255
```

Para representar 256 em binário, precisamos de outra posição:

```text
256 = 100000000
```

Há nove bits nessa última escrita. Acrescentar um bit dobra a quantidade de padrões disponíveis; não aumenta o limite em apenas uma unidade.

A forma geral para n bits sem sinal é de 0 até `2^n − 1`. Para dezesseis bits, isso significa 65.536 padrões e maior valor igual a 65.535. Como os dezesseis bits podem ser agrupados em dois bytes, um campo de dois bytes comporta essa faixa quando o formato o define como inteiro sem sinal.

Essa última condição não é detalhe: “dois bytes” informa o tamanho, não obriga o programa a interpretá-los como um número de zero a 65.535.

## E quando o número é negativo?

Precisamos de outra convenção para representar valores negativos. Uma delas é o **complemento de dois**. Nesse sistema, o bit mais à esquerda recebe peso negativo, enquanto os demais preservam os pesos positivos. Para oito bits, os pesos são `−128, 64, 32, 16, 8, 4, 2, 1`. [S1](referencias.md#s1)

A mesma sequência que antes valia 255 passa a ser:

```text
11111111 = −128 + 64 + 32 + 16 + 8 + 4 + 2 + 1 = −1
```

Nada nos oito símbolos avisa sozinho qual interpretação escolher. É o tipo do campo ou a operação do programa que estabelece se o valor é sem sinal ou com sinal em complemento de dois.

Compare os extremos nessa segunda convenção:

```text
10000000 → −128
01111111 →  127
```

Continuam existindo 256 padrões. Agora eles estão distribuídos entre valores negativos, zero e valores positivos. Não criamos mais combinações; mudamos a maneira de utilizá-las.

Essa é uma primeira aproximação, não uma promessa de que qualquer formato com números negativos usa essa convenção. Sempre precisamos identificar largura e regra de interpretação. O estudo das operações de processadores e linguagens voltará ao assunto.

## Quando o resultado não cabe

Imagine um contador fictício limitado a oito bits sem sinal. Ele está em 255, e uma operação tenta somar 1. O resultado matemático é 256, mas ele não cabe nas oito posições desse campo. Esse tipo de situação é chamado de **estouro**, ou *overflow*.

Se o mecanismo desse exemplo guardar somente os oito bits menos significativos — os oito da direita —, o padrão retido será `00000000`. Isso não muda a conta matemática: descreve a perda da posição adicional no armazenamento limitado.

Não generalize o comportamento para qualquer linguagem. Um ambiente pode rejeitar a operação, sinalizar erro, trabalhar com representação maior ou adotar regras próprias. A largura e as regras precisam acompanhar a explicação. Aqui definimos explicitamente a retenção de oito bits como uma hipótese de funcionamento do contador, não como resultado universal.

A conexão com segurança pode ser vista sem construir uma exploração. Se uma etapa do programa verifica o resultado amplo e outra utiliza um valor reduzido, as duas podem tomar decisões sobre quantidades diferentes. No exemplo, 256 e 0 não autorizariam necessariamente a mesma ação. Descobrir se isso ocorre em um sistema exigiria examinar suas operações; a possibilidade conceitual não prova uma vulnerabilidade.

## Dois bytes também precisam de uma ordem

Considere o inteiro `0x1234`. Ele vale `1 × 4096 + 2 × 256 + 3 × 16 + 4`, ou 4660 em decimal. Para representá-lo como dois bytes, precisamos escolher qual vem primeiro.

Em **big-endian**, o byte de maior peso vem antes: `12 34`. Em **little-endian**, vem primeiro o de menor peso: `34 12`. Esses nomes descrevem a ordem dos bytes de um valor com vários bytes; não significam que devemos inverter os bits dentro de cada byte. [S5](referencias.md#s5)

Se recebermos `12 34` e interpretarmos como inteiro sem sinal de dois bytes, teremos:

```text
big-endian:     0x12 × 256 + 0x34 = 4660
little-endian:  0x34 × 256 + 0x12 = 13330
```

O conteúdo recebido é o mesmo. A regra de leitura produz valores diferentes. O formato ou protocolo precisa definir a ordem; a pessoa que abre uma ferramenta não deveria adivinhá-la pela aparência do número.

A essa questão chamamos **endianness**, ou ordem de bytes. Ela não transforma toda sequência de bytes em um número único. Antes de discutir a ordem, ainda precisamos estabelecer quais bytes pertencem ao campo e qual é seu tipo.

## Tamanho de arquivo e taxa não são a mesma medida

Um arquivo com 1.000.000 de bytes contém 8.000.000 de bits. A conta é uma conversão de unidade, não uma alteração do arquivo.

Os prefixos também importam. Nas convenções apresentadas pelo NIST, `kB` corresponde a mil bytes e `KiB`, um kibibyte, a 1024 bytes. `MB` corresponde a um milhão de bytes e `MiB`, um mebibyte, a 1.048.576 bytes. Não são grafias alternativas da mesma quantidade. [S3](referencias.md#s3)

| Expressão | Quantidade de bytes |
| --- | ---: |
| 1 kB | 1.000 |
| 1 KiB | 1.024 |
| 1 MB | 1.000.000 |
| 1 MiB | 1.048.576 |

Um limite descrito somente como “1 mega” deixa a convenção implícita. Em documentação técnica, convém registrar a unidade e a regra que o sistema realmente utiliza.

Uma taxa acrescenta o tempo. `Mbit/s` expressa megabits por segundo; `MB/s`, megabytes por segundo. A conversão de 100 Mbit/s é 12,5 MB/s. Isso não garante uma transferência de arquivo nessa velocidade: é somente a equivalência de unidades, sem descontar mensagens de controle, outros tráfegos ou limitações de execução.

A pergunta que reúne esta seção é simples: **estamos contando padrões, interpretando um número, medindo armazenamento ou medindo uma taxa?** Usar a unidade correta impede que respostas a perguntas diferentes pareçam contraditórias.
